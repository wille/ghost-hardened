# Hardened Ghost image

A drop-in alternative to the official `ghost:6` image. It uses the same Ghost build, pinned by digest, and runs it locked down.

| Layer | What it does |
|---|---|
| Distroless runtime (`cc-debian12:nonroot`) | Removes the shell, package manager, ghost-cli and npm/pnpm. Ghost runs as uid 65532. |
| Read-only code | `/ghost` is root-owned and read-only, so Ghost can't modify itself. Only `/ghost/content` is writable. |
| Node permission model | Blocks child processes and WASI. Filesystem reads are limited to `/ghost` and `/tmp`, and writes to `/ghost/content` and `/tmp`. |
| `addon-guard.js` (preloaded with `--require`) | Allows native addons only from `/ghost/current/node_modules`, so a `.node` file dropped in the content volume can't escape the permission model. Applies to worker threads too. |
| `--disable-proto=delete` | Removes `__proto__`, cutting off a common prototype-pollution vector. |
| Container runtime (`compose.yaml`) | Read-only root filesystem, `noexec` `/tmp` tmpfs, `cap_drop: ALL`, `no-new-privileges`, and limits on processes and memory. |

## Differences from the official image

- **Paths:** Ghost lives at `/ghost` and content at `/ghost/content`, instead of `/var/lib/ghost`. fs-extra stats every parent directory when copying, and Node's filesystem grants are recursive, so a deeper path would mean granting read on `/var`.
- **Migrating:** mount your existing content volume at `/ghost/content`. Its files must be owned by uid 65532.
- **Bundled themes:** Casper and Source are copied into the volume rather than symlinked, because Node's permission model forbids `symlink()`. They are refreshed automatically when the image ships a new version.
- **Logging:** logs go to stdout only, never to files.

## Verified (Ghost 6.77.0, Node 22.23.5)

- **Working:** sqlite and MySQL 8.4, admin setup and login, posts, image upload and sharp resizing, theme upload and activation, database export and import, the healthcheck, and restarts.
- **Blocked under the image's flags:** `child_process` (including through `process.binding` and inside workers), reads of `/etc` and `/proc`, writes to Ghost's code and config, WASI, and native addons outside the release tree.

## Not covered (Node 22 limits)

- **Network:** outbound network is unrestricted. Node 22 has no `--allow-net`; enforce egress with a network policy or firewall.
- **Secrets:** the config and environment are readable by Ghost itself, so database and SMTP credentials remain exposed to anyone with code execution in the process.

## Usage

```bash
cp .env.example .env   # fill in
docker compose up -d --build
```

To upgrade, bump the `ghost:` tag and digest in the Dockerfile's first `FROM` line. Dependabot opens these PRs weekly.

## Supply chain

CI ([.github/workflows/build.yml](.github/workflows/build.yml)) builds with Docker's official [`docker/github-builder`](https://github.com/docker/github-builder) reusable workflow and pushes `linux/amd64` and `linux/arm64` images to `ghcr.io/wille/ghost-hardened`. Each push to `master` and each `v*` tag produces:

- **Signed SLSA provenance and an SBOM:** generated by an isolated BuildKit and signed keyless by Docker's builder workflow. The `verify-provenance` job checks them.
- **A cosign signature on the image:** signed keyless with Sigstore by this repo's workflow, then verified in the same run.

All actions are pinned to commit SHAs, and the base images to digests. Dependabot keeps both current.

To verify an image before deploying it, replace `<tag>`:

```bash
cosign verify ghcr.io/wille/ghost-hardened:<tag> \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github.com/wille/ghost-hardened/\.github/workflows/build\.yml@refs/(heads/master|tags/v.+)$'
```

To inspect the provenance:

```bash
docker buildx imagetools inspect ghcr.io/wille/ghost-hardened:<tag> --format '{{json .Provenance}}'
```

The exact cosign commands for verifying provenance are printed in each build job's log.
